Playbook.
Scenario - We want to install and start nginx.

we give "---" in the file, indicates that this is a yaml file
then we can start writing the playbook.

there can be sometimes when we want to run the playbook as root user
so we can give the user as root in the playbook

we can write multiple playbook also in one yml file

- name: first playbook
- name: second playbook

yaml script:

---
- name: Install and start nginx
  hosts: all
  become:true

  tasks:
    - name: Install nginx
      apt:
        name: nginx
        state: present
equivalent to 
shell: apt install nginx

we use the above format to write the playbook so that the script can be kept as generic.



ansible-playbook -i inventory(file_name) <playbook-name>

Keep the syntax in check for the ansible playbook yaml script
will get errors due to indentations as per yaml syntax.

So ansible came up with ANSIBLE ROLES.

Ansible Roles are efficient way to write complex playbooks, which help to create the playbook and maintains Readability also.
Properly segregate and structure the playbook

Why use ansible roles, because it can help write the ansible playbook in a very
structured manner and in a most efficient way.

ansible-galaxy role init kubernetes.
running this command creates kubernetes folder which has the below data which gets created to help in writing the playbooks
