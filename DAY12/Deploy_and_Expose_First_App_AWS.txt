Resolution --> 

1) Remove the .git file from the sub repo, and convert it into normal folder,
removing .git will tell git not to track this, as .git is the 
folder which gets created after doing git init, so an approach to solve this problem.

2) You want AWS-Session to remain its own independent GitHub repository.
Then you should not commit it inside ZeroToHeroDevOps.
Instead, keep working with it separately.

"160000 df1f05dcff31244bc68e3b65aa78b24c34816990 0 DAY12/AWS-Session"
The mode 160000 has a special meaning in Git:
160000 = This path is a Git submodule (gitlink), not a normal folder.
Even though you deleted the inner .git folder, your main repository still remembers AWS-Session as a submodule.

Use this command to remove above error :

git rm --cached DAY12/AWS-Session

and then follow normal git add, commit, push
