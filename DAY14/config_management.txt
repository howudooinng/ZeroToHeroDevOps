What is this Push and Pull mechanism model?

Scenario-----------------------------------------------------

--> Suppose, There is a DevOps Engineer who Manages the AWS 
configuration of an organization who has created
10 EC2 instances and his responsibility is to manage 
these 10 ec2 instances. 

What does manage here means ?
Suppose there is a requirement to install GIT on all the 
ec2 servers which has been created by this DevOps
engineer, so that it can be provisioned to the developers 
who are joining the team.

So this is a scenario where he can't manually run scripts 
on all 10 ec2 servers by logging into each server and 
manually installing GIT on each and every server.

So he uses ANSIBLE which uses PUSH mechanism <--

What is Push Mechanism? 

DevOps Engineer can write his ANSIBLE playbook on his laptop 
and execute the playbook. 
The script will be exceuted and all the 10 ec2 instances 
will be installed with GIT.

ANSIBLE Uses a AGENTLESS Model which makes CM very easy.

With ansible -- it's a agentless model, just put names of 
these servers, on inventory file, 
just put ip addresses(Public),
just have password less authentication.
Laptop should connect with ec2 instances without password.


Puppet follows - configure master slave architecture.
This DevOps Engineer, creates master node through which 10 ec2
servers as slave are configured and then it can be updated.

Why is this important functionailty provided by Ansible ?
--> we work in dynamic enviroment, and we have to 
scale up and scale down our servers. 

Since we have to frequently scale up and scale down our 
servers, so ansible is very important.


Dynamic Inventory files in Ansible -->
Ansible is capable of detecting new servers which gets created,
on AWS and automatically ansible starts managing it with the 
playbook instructions.



Disadvantages for ANSIBLE :
