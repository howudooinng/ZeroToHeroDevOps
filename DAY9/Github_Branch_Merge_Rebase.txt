Release Branch --> This branch is created when there is a release to production. The changes
which are done through many features are in the MAIN branch along with the old production code 
which is currently running in production.

So, now the release branch has the current commits + the old prod code. so the release branch is 
now getting tested by the QA team and when they find a bug, it gets fixed only in the release 
branch and not in the main, after everything is stable in the release branch, it gets deployed 
to production, and after everything goes well, we merge the release branch to main branch as well
so that the changes made in the release branch during testing phase gets added as well to the main branch,
beacause if not done like that, it will again give error in the next release.


Now coming to MERGE and REBASE, How it works and why it is important ?
How organizations use merge and rebase in GIT during project?

Git rebase → doesn't give any extra commit id and used for making the commit history linear.
It is commonly used by developers to update their 
local feature branch with the latest changes from main (or develop) 
so they work on top of the newest history and reduce merge conflicts later. 

Git merge → gives one extra commit id mentioning git merge 
It is commonly used to integrate completed work into another branch 
(e.g., feature → main or develop) after development, testing, and review.

When a commit is done in feature and Pushed to github, github automatically sees that 
a new commit is there and gives the option to compare and pull request, which 
can be used to raise a PR, add comments and process ahead with these three options which are:

create a merge commit == git merge <feature_branch_name>
squash and merge      == 'n' number of commits in feature branch, only 1 in main branch
rebase and merge      == commits are rebased and merged to main branch 

| Option                    | Merge Commit | Commit History Preserved | Linear History | Typical Use                                              |
| ------------------------- | ------------ | ------------------------ | -------------- | -------------------------------------------------------- |
| **Create a merge commit** | ✅ Yes        | ✅ Yes                    | ❌ No           | Long-lived features, preserving branch history           |
| **Squash and merge**      | ❌ No         | ❌ No (commits combined)  | ✅ Yes          | Small features, clean history                            |
| **Rebase and merge**      | ❌ No         | ✅ Yes                    | ✅ Yes          | Teams that prefer a linear history without merge commits |
